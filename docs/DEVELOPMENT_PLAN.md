# WebGL 게임형 그래픽스 포트폴리오 블로그 — 구성·개발 계획서

> 첫 버전의 계획서다. 구, 발판, 점프처럼 지금은 바뀐 내용이 남아 있고, 바뀐 결정은 날짜와 함께 일부만 적혀 있다. 현재 구조와 기능은 [PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md), 기능별 규칙은 [README.md](README.md)의 색인을 본다. 발판(뒤의 작동 영역)과 콘텐츠 인터페이스는 등록된 콘텐츠가 없어 2026-11-22에 지웠다 ([rules/world.md](rules/world.md)).

## 1. 배경과 목표

그래픽스 개발 작업을 일반 게시판이 아니라 **직접 플레이하는 공간**으로 보여주는 개인 사이트를 만든다. 사이트 자체가 작품이다. 처음에는 자체 WebGL2 엔진으로 만들었고, 2026-11-15에 렌더링을 three.js로 옮겼다 ([적용 분석](analysis/threejs.md)).

- 플레이어는 단순한 **구**다. 굴리고 튕겨서 공간을 돌아다닌다.
- 공간의 **바닥 발판**을 밟으면 해당 그래픽스 콘텐츠가 활성화된다.
- 준비된 콘텐츠가 아직 없으므로, 첫 버전의 콘텐츠는 **구의 색을 바꾸는 기능**이다.
- 이후 셰이더 데모는 발판을 추가하는 방식으로 늘려간다.

**첫 버전의 완료 기준:** 공개 URL에서 구를 굴리고 점프해 발판을 밟으면, 구의 색이 부드럽게 바뀐다.

## 3. 기술 구성

개발 도구는 **Vite + TypeScript**, 테스트는 **Vitest**를 쓴다. 모두 개발 시에만 쓰이며 배포 결과물에는 직접 작성한 코드만 들어간다. GLSL 파일은 Vite의 `?raw` 임포트로 불러온다.

```
GameBlog/
├─ index.html
├─ src/
│  ├─ main.ts            진입점, 게임 루프
│  ├─ engine/            게임을 모르는 범용 코드
│  │  ├─ gl.ts           컨텍스트 생성, 컨텍스트 손실 처리
│  │  ├─ shader.ts       컴파일·링크, 오류 표시
│  │  ├─ mesh.ts         구·박스·평면 절차 생성
│  │  ├─ math.ts         vec3·mat4·quat
│  │  ├─ renderer.ts     그림자 패스 → 메인 패스
│  │  └─ input.ts        키보드, 포인터 잠금
│  ├─ physics/           구-평면·구-박스 충돌, 고정 시간 간격
│  ├─ game/
│  │  ├─ player.ts       구의 이동·점프·회전
│  │  ├─ cameraRig.ts    3인칭 추적 카메라
│  │  ├─ pressurePlate.ts 발판 상태와 눌림 애니메이션
│  │  └─ world.ts        월드 조립
│  ├─ content/
│  │  ├─ types.ts        GraphicsContent 인터페이스
│  │  ├─ registry.ts     발판 ↔ 콘텐츠 연결 데이터
│  │  └─ sphereColor.ts  첫 콘텐츠
│  ├─ shaders/           *.vert, *.frag
│  └─ ui/                조작 안내, 현재 콘텐츠 이름
└─ .github/workflows/deploy.yml
```

### 확장의 핵심: 콘텐츠 인터페이스

발판은 콘텐츠의 내용을 모른다. 앞으로 데모를 추가할 때 **콘텐츠 파일 하나와 등록 한 줄**만 더하면 되도록 한다.

```ts
interface GraphicsContent {
  id: string;
  label: string;
  activate(ctx: ContentContext): void;
  deactivate(ctx: ContentContext): void;
  update?(dt: number, ctx: ContentContext): void;
}
```

### 렌더링

- Cook-Torrance PBR 재질과 방향광 1개
- PCF 그림자 맵
- 환경광, ACES 톤 매핑, sRGB 출력
- 렌더링 해상도는 devicePixelRatio를 최대 2로 제한

**구의 표면 무늬:** 단색 구는 회전이 눈에 보이지 않아 굴러가는 느낌이 나지 않는다. 그래서 오브젝트 공간 기준의 은은한 줄무늬를 넣고, 색이 바뀌어도 무늬는 유지한다.

### 물리와 조작

- 물리는 렌더링과 분리해 **120Hz 고정 시간 간격**으로 계산하므로 모니터 주사율과 무관하게 같은 움직임을 보장한다.
- 이동 입력은 카메라 방향 기준의 가속도로 변환하고, 구의 회전은 속도에서 계산한다.
- 착지 시 반발력으로 튕긴다. 점프는 처음에 있었으나 2026-11-15에 제거했다.
- 월드는 낮은 벽으로 둘러싸고, 그래도 떨어지면 시작 지점에서 다시 시작한다.

### 발판 동작

- 구가 발판 위에 닿으면 스프링처럼 눌리며 콘텐츠가 활성화된다.
- 구가 발판을 완전히 벗어나야 다시 작동할 수 있어, 경계에서 반복 작동하지 않는다.
- 활성 콘텐츠는 한 번에 하나이며, 활성 발판은 은은하게 빛난다.
- 구의 색은 선형 색공간에서 약 0.3초 동안 전환한다.
- 첫 월드에는 색 발판 4개와 기본색 복귀 발판 1개를 둔다.

### 예외 상황 처리

- **WebGL2 미지원:** 안내 화면 표시
- **컨텍스트 손실:** 복구 시 GPU 리소스 재생성
- **탭 비활성:** 일시 정지, 복귀 시 물리 시간이 한꺼번에 흐르지 않도록 제한
- **포인터 잠금 해제:** 일시 정지 화면 표시
- **모바일 접속:** 처음에는 "PC에서 플레이해 주세요" 안내였고, 2026-11-17에 터치 조작으로 대체

## 4. 개발 단계

| 단계 | 내용 | 완료 확인 |
|---|---|---|
| M0 준비 | git 초기화, Vite·TS·Vitest 구성 | 빈 캔버스가 화면을 채움 |
| M1 렌더링 | 수학 라이브러리, 셰이더, 메시, PBR, 그림자 | 스튜디오에 정지한 구와 그림자가 보임 |
| M2 플레이 | 물리, WASD·점프, 3인칭 카메라 | 구를 굴리고 튕길 수 있고 벽에 막힘 |
| M3 상호작용 | 발판, 콘텐츠 인터페이스, 구 색상 변경 | 발판을 밟으면 색이 부드럽게 바뀜 |
| M4 다듬기 | 조작 안내, 일시 정지, 예외 처리, 조작감 조정 | 처음 온 사람이 설명 없이 플레이 가능 |
| M5 배포 | GitHub Actions로 Pages 자동 배포 | 공개 URL에서 동작 |

M5에는 사용자의 GitHub 저장소가 필요하다. Vite의 `base`를 상대 경로(`./`)로 설정해 저장소 이름과 무관하게 동작하며, 저장소 생성과 공개는 그 시점에 다시 확인한다.

## 5. 첫 버전 이후 (이번 범위 아님)

1. **셰이더 데모 콘텐츠:** 발판을 밟으면 바닥이나 구의 셰이더가 바뀌는 기능
2. **후처리:** 블룸, SSAO 등 기법 자체를 콘텐츠로 전시
3. **게임 요소:** 공간 확장, 발견 요소, 사운드
4. **모바일:** 가상 조이스틱은 2026-11-17에 추가. 성능 조정은 남아 있음

사이트의 내용은 글이 아니라 그래픽과 플레이 상호작용으로만 전달한다. 글 게시 기능은 이 컨셉에 맞지 않아 두지 않는다.

## 6. 검증 방법

- **자동 테스트 (`npm test`):** 수학 함수, 구 충돌과 반발, 발판 상태 전환(눌림, 재작동 조건, 경계 반복 방지)
- **빌드 (`npm run build`):** 타입 오류 없이 정적 파일 생성
- **실행 확인 (앱 내 브라우저에서 개발 서버 실행):**
  1. 콘솔과 WebGL 오류가 없는지 확인
  2. 구 이동, 점프, 벽 충돌, 시점 회전 확인
  3. 각 발판을 밟아 색 전환과 기본색 복귀 확인
  4. 발판 경계에서 반복 작동하지 않는지 확인
  5. 포인터 잠금 해제와 탭 전환 후 정상 복귀 확인
- **성능:** 일반 PC의 내장 그래픽에서 60fps 유지를 목표로 측정
- **배포 후:** 공개 URL에서 위 2~3번 재확인
