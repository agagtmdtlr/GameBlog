## 1. 컨셉

사이트 전체가 하나의 3D 플레이 공간이다. 내용은 **글이 아니라 그래픽과 플레이 상호작용으로만 전달**한다. 방문자는 작은 행성 위에서 구체 몸에 두 다리가 달린 캐릭터로 걸어 다니고, 표면에 칠해진 원형 영역에 들어가 콘텐츠를 켠다(지금은 등록된 콘텐츠가 없다). 표면에는 스플라인 선로를 따라 도는 기차가 있다. 하늘에는 행성을 도는 해, 제자리에서 자전하는 위성, 얼굴이 있는 별들이 떠 있다. 렌더링은 three.js로 하고, 셰이더는 직접 작성한다.

## 2. 기술 구성

| 항목 | 내용 |

| 코드 규모 | TypeScript 3,556줄, 셰이더 264줄, CSS 257줄, 테스트 1,233줄, Blender 스크립트 179줄 |

## 4. 구조

### 의존 방향

```
main.ts ─┬─ game/ ─┬─ content/
         │         ├─ physics/ ─ engine/math
         │         └─ engine/
         ├─ engine/
         └─ ui/
```

- `engine/`은 게임 규칙을 모른다.
- `World`는 GPU와 DOM에 의존하지 않아 브라우저 없이 테스트할 수 있다.
- `Renderer`는 게임 상태를 들고 있지 않다. three.js는 `engine/renderer.ts`, `engine/billboardRenderer.ts`, `engine/contentRenderers/`, `main.ts`에서만 쓴다.
- `Renderer`는 특정 콘텐츠를 모른다. 콘텐츠 전용 그리기는 `ContentRenderer`를 상속한 클래스가 맡는다.
- 콘텐츠는 `ContentContext`를 통해서만 월드에 영향을 준다. 작동 영역은 콘텐츠의 내용을 모른다.

### 프레임 흐름

1. `main.ts`가 입력을 읽어 카메라 기준 이동 방향을 계산한다.
2. `FixedStepper`가 경과 시간만큼 `World.fixedStep`을 120Hz 간격으로 실행한다. 프레임 시간은 최대 0.1초로 제한한다.
3. `fixedStep`은 해의 궤도 진행, 위성 자전, 기차 진행, 캐릭터 물리 몸체의 이동과 충돌, NPC 이동과 캐릭터끼리 밀어내기, 걸음(`Walker`), 영역 판정, 활성 콘텐츠 갱신을 순서대로 처리한다.
4. 카메라가 보간된 물리 몸체 위치를 따라간다.
5. `World.buildDrawList`, `buildBillboards`(별·햇살·해 눈, [analysis/billboard.md](analysis/billboard.md)), `environment`(해 방향의 직사광), `buildContentFrames`가 그릴 내용을 만들고, `Renderer`가 그림자 패스와 메인 패스를 실행한 뒤 값이 있는 콘텐츠 렌더러를 호출한다. 지금은 콘텐츠 렌더러가 없다.

### 게임 상태

| 상태 | 진입 | 동작 |
|---|---|---|
| `start` | 페이지 로드 | 시작 화면 표시. 물리 정지 |
| `playing` | 시작·계속하기 버튼 | 입력과 물리 진행. 포인터 잠금 요청 |
| `paused` | Esc, 포인터 잠금 해제, 탭 전환 | 일시 정지 화면 표시. 물리 정지 |

상태와 무관하게 렌더링은 계속된다.

## 5. 기능

### 조작

| 입력 | 동작 |
|---|---|
| W A S D, 방향키 | 카메라 기준으로 걷기. 방향은 캐릭터가 있는 곳의 표면을 따른다 |
| 마우스 | 시점 회전. 포인터 잠금이 안 되면 왼쪽 버튼 드래그 |
| Esc | 일시 정지 |
| 터치, 화면 왼쪽 절반 | 누른 자리에 생기는 가상 조이스틱. 기울인 만큼 걷기 |
| 터치, 화면 오른쪽 절반 | 드래그로 시점 회전 |
| 일시 정지 버튼 (터치 기기만) | 일시 정지 |

### 물리

- 충돌 구 반지름 0.88 × `CHARACTER_SCALE`(1.5) = 1.32. 보이지 않는 구이며 중심이 캐릭터 몸의 중심이다. 지면과 공중의 가속도와 감쇠를 따로 적용한다.
- 중력(22)은 행성 중심을 향한다. 속도를 중심 방향과 표면에 접하는 방향으로 나눠, 입력과 감쇠는 접하는 방향에만 적용한다.
- 반발 계수 0.45. 느린 충돌(법선 속도 2.0 이하)은 튕기지 않아 바닥에서 떨리지 않는다.
- 점프는 없다 (2026-11-15 제거). 캐릭터는 걸어서만 움직인다.
- 바닥에서 잠깐 떠도 0.1초 동안은 지면 가속과 감쇠를 유지한다.
- 굴러가는 회전은 계산하지 않는다. 몸의 방향과 발은 `Walker`가 정한다 ([analysis/character.md](analysis/character.md)).
- 충돌체는 높낮이가 있는 땅(구-땅 충돌, 비탈에서 미끄러지지 않게 위쪽으로 밀어냄), 집 자리·로켓 자리 상자(구-방향 있는 상자 충돌, 2026-11-21 사용자 요청), 둥근 지형물의 캡슐(2026-11-22)이다. 상자에 부딪히면 튕기지 않고 면을 따라 미끄러진다. 위를 향한 면에 닿으면 서 있는 것으로 본다. 상자는 `World`가 `Player.step`의 `obstacles`로 넘긴다. 다리와 발은 상자를 모르므로, 벽에 붙으면 발이 상자에 묻힐 수 있다. 작동 영역은 충돌체가 아니라 표면에 칠한 판정 영역이다.
- 최고 속도로 걸어도 표면에서 뜨지 않는다. 한 바퀴를 도는 테스트가 이를 확인한다.

### 월드

- 원점이 중심이고 반지름이 18인 행성 하나다 (둘레 약 113). 땅에는 완만한 언덕과 잔물결이 있고, 종 모양 언덕·둥근 기둥·공·막대사탕 같은 파스텔 지형물이 흩어져 있다. 선로·집·로켓·시작 지점 둘레는 평평하다 (2026-11-22 사용자 요청, [analysis/terrain.md](analysis/terrain.md)). 벽과 가장자리가 없어 떨어질 곳이 없고, 다시 시작하는 처리도 없다.
- 캐릭터는 꼭대기 `(0, 18.88, 0)`에서 시작해 -Z 쪽을 바라본다.
- 캐릭터 집이 놓일 자리에 푸른 회색 상자(폭 3.2, 높이 2.8, 깊이 3.2)를 둔다 (2026-11-21 사용자 요청). 위치는 위도 66, 경도 180으로, 시작 지점 정면 약 7.5 거리이고 해가 드는 쪽이다. 정면이 시작 지점을 향한다. 위치, 크기, 색은 장면 파일 `scenes/surface.json`의 `house`에서 바꾼다.
- 로켓이 놓일 자리에 단순화한 주황색 로켓 모형(달걀 몸통, 짧은 다리 넷, 정면의 둥근 창, 옆문, 리벳 줄)을 세운다. 처음에는 붉은 정육면체였고, 사용자가 보여 준 리벳 박힌 달걀 모양 로켓 사진을 단순화해 바꿨다 (2026-11-21 사용자 요청). 충돌은 모형을 감싼 상자(폭 6.5, 높이 7.5)로 한다. 처음 크기(폭 2.6, 높이 3.0)에서 2.5배로 키웠다 (2026-11-21 사용자 요청). 위성으로 향하는 부근이라는 요청에 따라 위성 바로 아래 표면(위도 약 30, 경도 약 207.5)에 두었고, 위쪽이 위성을 향한다. 위치는 `MOON.direction`에서 계산하므로 위성을 옮기면 따라간다. 집 자리와 같이 충돌체다. 크기와 색은 장면 파일 `scenes/surface.json`의 `rocket`에서 바꾼다.
- 시작 지점을 둘러싸고 위도 46~54 사이를 물결치는 닫힌 스플라인 선로에 기관차와 객차 셋이 끝없이 돈다. 차량은 움직이는 충돌 상자라 선로 위의 캐릭터를 밀어낸다 (2026-11-21 사용자 요청, [analysis/train.md](analysis/train.md)).
- 행성 주변 하늘(시작 시점 왼쪽 위, 거리 40)에 충돌구가 패인 회색 위성이 떠서 제자리에서 자전한다 (2026-11-21 사용자 요청).
- 주황색 해가 행성 중심에서 70 떨어진 궤도를 48초에 한 바퀴 돈다. 직사광이 해를 따라 움직여 낮과 밤이 바뀌고, 밤 쪽은 간접광으로만 보인다. 해는 둘레의 햇살과 캐릭터를 바라보는 눈을 가지며, 궤적이 가는 고리로 보인다 ([analysis/sun.md](analysis/sun.md)).
- 행성 중심에서 110~200 떨어진 곳에 얼굴이 있는 별 48개가 카메라를 보며 떠 있다 ([analysis/starfield.md](analysis/starfield.md)).
- 카메라의 위쪽은 캐릭터가 있는 곳의 표면 바깥 방향이다. 좌우 각도 대신 표면에 접하는 진행 방향을 들고 다녀 극점에서도 뒤집히지 않는다.
- 검은 배경에 파스텔 무지개 색이 물결치는 몽환적인 행성을 둔다. 땅과 지형물은 가장자리가 은은하게 빛나고 밤 쪽에서도 스스로 조금 빛난다. 처음에는 흰색 무채색이었고 2026-11-22에 사용자 요청으로 바꿨다. 캐릭터는 노랑(#FCC812)으로 고정이다.
- 플레이어와 같은 다리에 색과 몸 모양(구, 정육면체, 피라미드)이 다른 NPC 5마리(하늘색, 분홍, 초록, 보라, 주황)가 행성 둘레에서 시작해 아무 곳으로 천천히 걸어갔다가 잠깐 서기를 되풀이한다. 하늘색이 집 자리 옆에서 시작한다. 플레이어와 NPC는 서로 통과하지 못한다 (2026-11-21 사용자 요청, [analysis/npc.md](analysis/npc.md)).

### 작동 영역과 콘텐츠

지금은 등록된 콘텐츠가 없어 행성 표면에 영역이 없다. 예전의 행성 표면 색 변경 콘텐츠(기본색, 코랄, 앰버, 틸, 블루 영역)는 새 시스템을 넣기 전에 정리하려고 2026-11-21에 사용자 결정으로 지웠다. 참고 구현은 커밋 `1c3831b`의 `content/planetColor.ts`, `game/colorTransition.ts`에 있다. 아래는 콘텐츠를 등록하면 따라오는 영역 동작이다.

- 위치는 도 단위다. 위도 90이 시작 지점이고, 경도 180이 시작할 때 바라보는 방향이다.
- 영역은 시작할 때 해가 드는 쪽에 둔다. 해가 궤도를 돌므로 플레이 중에는 영역이 밤 쪽에 놓일 수 있다.
- 영역은 모델 없이 행성 표면에 칠한 원(표면 반지름 1.5)이다. 안쪽은 영역 색으로 물들고 경계에 어두운 선이 있다.
- 캐릭터 몸의 중심이 원 안으로 들어오면 작동한다. 높이는 보지 않는다. 경계에서 충돌 구 반지름만큼 더 벗어나야 다시 작동하므로 경계를 오가도 반복 작동하지 않는다.
- 켜진 영역은 빛나고, 캐릭터가 올라선 영역은 경계선이 밝아진다.
- 활성 콘텐츠는 한 번에 하나이며, 처음에는 켜진 콘텐츠가 없다.
- 왼쪽 아래 HUD에 현재 콘텐츠의 이름과 영역 색을 표시한다. 켜진 콘텐츠가 없으면 HUD를 숨긴다.

### 렌더링

- **재질:** 툰 셰이딩과 방향광 1개. 외곽선 없이 직사광(그림자 포함)을 4단계로 나누고, 거칠기에 따라 한 단계짜리 하이라이트를 둔다. 앰비언트는 하늘·땅 평균색 하나다 (2026-11-21, 전에는 Cook-Torrance PBR). 밤인 곳은 해 반대쪽에서 오는 약하고 푸른 달빛(그림자 없음)과 푸른 밤 앰비언트를 받는다
- **three.js:** `WebGLRenderer`, `Scene`, 기본 지오메트리, `GLTFLoader`(캐릭터 다리 스킨 메시, CPU 스키닝), 카메라, 렌더 타깃을 쓴다. 조명과 재질 계산은 내장 재질 대신 아래의 직접 작성한 셰이더가 한다
- **그림자:** 2048px 깊이 맵, 3×3 PCF, 원점 기준 반경 24 고정. 광원 방향은 해를 따라 매 프레임 바뀐다. 해와 위성은 범위 밖이라 그림자를 드리우지 않는다
- **빌보드:** 별, 햇살, 해 눈을 텍스처 아틀라스 한 장과 인스턴스 그리기 한 번으로 그린다 ([analysis/billboard.md](analysis/billboard.md))
- **위성:** 정이십면체 구를 충돌구·바위 덩어리 모양으로 밀어 만든다 ([analysis/moon.md](analysis/moon.md))
- **간접광:** 하늘·지면 2색 반구광과 환경 맵 없는 반사 근사 (Karis 2014)
- **접지감:** 캐릭터 몸이 행성 표면에 만드는 해석적 앰비언트 오클루전
- **출력:** ACES 톤 매핑, sRGB 변환, 안티에일리어싱, devicePixelRatio 최대 2
- **표면 무늬:** 행성의 격자로 이동감을 준다. 격자는 구를 정육면체 여섯 면으로 나눠 그려 극점에서 선이 몰리지 않는다

## 6. 콘텐츠 확장

규칙은 [rules/content.md](rules/content.md)에, 유형별 수정 파일과 렌더러 구조, 확인 방법은 [analysis/content.md](analysis/content.md)에 정리되어 있다.

[`registry.ts`](../src/content/registry.ts)의 `CONTENT_ENTRIES`에 등록하면 영역 표시, 판정, HUD 표시가 자동으로 따라온다. 지금 `ContentContext`는 비어 있어 다음 작업이 함께 필요하다.

1. `src/content/`에 `GraphicsContent`를 구현한 콘텐츠 파일을 추가한다.
2. 필요한 기능을 [`ContentContext`](../src/content/types.ts)에 더하고 `World`에서 연결한다.
3. 셰이더나 후처리를 바꾸는 콘텐츠라면 `src/engine/contentRenderers/`에 `ContentRenderer`를 상속한 클래스를 추가하고 그 폴더의 `registry.ts`에 등록한다. `Renderer`는 고치지 않는다.
4. `registry.ts`에 등록한다.

영역 위치는 위도와 경도로 직접 지정하며, 기존 테스트가 영역 간 간격, 영역 수(최대 8), 시작 지점과의 거리, 해가 드는 쪽인지를 검사한다.
