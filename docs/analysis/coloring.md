# 색칠 놀이 분석

선으로 나뉜 그림의 빈 곳을 누르면 그 판의 무작위 색이 채워지고, 모두 칠하면 완성되는 미니 게임(`src/games/coloring/`)의 구조와 수정 방법을 정리한 문서다.

- **규칙:** [rules/world.md](../rules/world.md)의 "컨셉", "구조"
- **색인:** [docs/README.md](../README.md)
- **분석 기준:** `feature/coloring` (2026-11-24, 커밋 `c99400d` 위에서 추가)
- **최신 여부 확인:** 아래 명령에 결과가 있으면 그 변경분만 확인해 이 문서를 고친다.

```bash
git log --oneline c99400d..HEAD -- src/games src/main.ts
```

## 놀이 규칙 (2026-11-24 사용자 요청)

- 참고 그림처럼 굵은 선으로 나뉜 흰 칸들이 있는 그림을 보여 준다. 칸을 누르면 색이 채워진다.
- 색은 고르지 않고 무작위로 주어진다. 판마다 색 묶음(8색)을 새로 뽑고, 누를 때마다 그 묶음에서 고른다. 그래서 같은 그림도 판마다 다르게 완성된다.
- 이미 칠한 칸을 다시 누르면 다른 색으로 바뀐다. 색은 지금 색과, 칠해진 이웃 칸의 색을 되도록 피한다.
- 모든 칸을 칠하면 클리어: 그림이 통통 튀고, 그림 아래 양쪽 모서리에서 색종이가 터져 오르고, 오림 글자 `CLEAR!`가 뜬다. 다시 하기 버튼이 노랗게 흔들린다.
- 7초 동안 누르지 않으면 안 칠한 칸이 노랗게 반짝여 남은 곳을 알려 준다.
- 화면의 글은 클리어 표시뿐이다. 버튼(메인으로, 새 색으로 처음부터)은 그림 아이콘이고, 진행 막대는 그 판의 색 묶음으로 칠한 띠다.

## 미니 게임 계층 (`src/games/`)

3D 엔진(`engine/`)은 캐릭터 이동, 포인터 잠금, 시작·일시 정지 화면을 전제로 해서, 누르기만 하는 2D 놀이는 엔진을 거치지 않는 계층으로 따로 두었다.

```
?game=<id> ── main.ts ── import('./games') ── findGame(id).start(#play)
```

| 파일 | 내용 |
|---|---|
| `src/games/game.ts` | `GameDefinition { id, start(root) }`. 게임이 `root` 안에 화면을 만든다 |
| `src/games/index.ts` | `GAMES` 목록과 `findGame` |

- `main.ts`가 `?game=`을 먼저 보고, 맞는 게임이 없으면 `?scene=`·메인 페이지로 넘어간다. 게임 화면에서는 `<html>`에 `is-game`을 붙여 엔진의 캔버스·안내 화면을 숨기고 `#play`(index.html)를 쓴다.
- 게임 코드는 `import()`로 따로 청크가 된다 (빌드 기준 `games-*.js` 약 20 kB, three.js 청크는 씬과 함께 쓴다).
- `src/layers.test.ts`가 검사한다: 게임은 `engine/`, `content/`, `home/`, 다른 게임을 가져오지 않고, `main.ts` 말고는 게임을 가져오지 않는다. three.js는 게임의 `graphics/`에서만 가져온다. 게임이 `lib/`을 가져오는 것은 된다.
- 메인 페이지 컷은 `"open": { "game": "<id>" }`로 게임을 연다 ([home.md](home.md)).

지금 게임: 색칠 놀이(`coloring`), 2048(`2048`, [game2048.md](game2048.md)).

새 게임 추가: `src/games/<게임>/index.ts`에 `GameDefinition`을 만들고 `GAMES`에 더한 뒤, `contents.json`의 컷에 `open.game`을 넣는다.

## 흐름

1. 그림 자리(`pictureRect`): 위에 버튼 줄(64px), 아래에 진행 막대(44px)를 두고 남은 곳의 가장 큰 정사각형.
2. 그림 픽셀 크기: 화면에 그려질 크기 × 기기 배율(최대 2)보다 크거나 같은 1024·1536·2048 중 가장 작은 것.
3. `rasterizeSvg`: 흰 면·검은 선 SVG를 캔버스에 그려, 픽셀마다 `어두운 정도 × 불투명도`를 선 진하기로 읽는다. 절반을 넘으면 선이다. 액자 바깥은 투명이라 0이다.
4. `labelRegions` ([regions.ts](../../src/games/coloring/regions.ts) 맨 위 설명):
   - 선이 아닌 픽셀을 4방향으로 이은 덩어리 가운데, 가장자리에 닿은 것(액자 바깥)은 0, 그림 넓이의 0.02%(1000칸 그림에서 약 14 × 14칸)보다 작은 것은 선으로 합친다.
   - 이웃: 가로·세로로 18칸(그림 기준, 선 굵기 8칸보다 넉넉히) 건너 본 픽셀이 다른 영역이면 맞닿은 것으로 본다.
   - 선 픽셀에는 가장 가까운 영역 번호를 번져 채운다. 선 위를 눌러도 가까운 칸이 칠해지고, 선의 흐린 가장자리 아래 색도 정해진다.
5. 누르기(`click`): 화면 좌표 → 그림 픽셀 → 영역 번호 → `ColoringState.paint` → `ColoringView.paintRegion`.

## 그리기 (`ColoringView`)

- 정사영 카메라, CSS px 좌표(y 위쪽 양수). 그림은 사각형 하나에 `RawShaderMaterial`(GLSL3)을 입힌다. 바탕색은 메인 페이지 종이색 `#fbf6ec`, 선은 `#2a221e`.
- 텍스처
  - 영역 번호: RGBA8, R·G에 16비트 번호. `NearestFilter`, 셰이더에서 `texelFetch`
  - 선 진하기: R8, 밉맵 선형 필터. 선으로 합친 작은 틈은 255로 칠해 검게 보인다
  - 영역 색: Float RGBA, 가로는 영역 번호, 세로 세 줄(새 색·칠한 시각 / 이전 색·번질 거리 / 누른 자리·안 칠함 표시). 칠할 때 이 텍스처만 다시 올린다
- 칠하기 연출: 누른 자리에서 0.45초 동안 원이 커지며 새 색이 번지고, 물결 앞에 밝은 띠가 지나간다. 번질 거리는 누른 자리에서 영역 상자 꼭짓점까지 가장 먼 거리다.
- 색은 sRGB 값을 셰이더에서 그대로 쓴다 (색 공간 변환 없음). 색종이(`MeshBasicMaterial`)는 `SRGBColorSpace`로 넣어 three.js가 변환한다.
- 색종이: `InstancedMesh` 180장. 그림 아래 양쪽 모서리에서 부채꼴로 쏘아 올리고, 중력·공기 저항·팔랑임으로 4.5초 동안 떨어진다.

## 그림 바꾸기·더하기

- 좌표는 1000 × 1000칸, 액자는 안쪽 40~960 (선 16), 모양 선은 8이다.
- 뒤에서 앞 순서로 흰 면·검은 선 모양을 쌓는다. 앞 모양이 뒤를 가려 선이 겹치지 않는다. 눈·코처럼 칠하지 않을 곳은 `dot`, `inked`로 검게 채우고, 입·무늬처럼 칸을 나누지 않는 선은 `line`으로 그린다.
- 모양 안을 나누는 선(로켓 띠, 고양이 이마, 아이스크림 콘 격자)은 `divided(모양, [선...])`가 모양으로 잘라 그린다.
- 30 × 30칸보다 작은 칸은 휴대폰에서 누르기 어렵고, 14 × 14칸보다 작으면 선으로 합쳐진다.
- 새 그림은 `pictures/<그림>.ts`에서 `pictureSvg([...])`로 짓고 `pictures/index.ts`의 `PICTURES`에 더한다. 판을 열 때 무작위로 고르고, 다시 하기는 같은 그림의 색만 새로 뽑는다.
- 그림은 참고 그림의 화풍(굵은 선, 점 눈, 서로 겹쳐 모인 캐릭터)만 따르고, 캐릭터는 새로 그렸다.

## 메인 페이지 미리 보기

`src/home/previews/coloring.svg`는 그림 SVG의 흰 면 일부(약 70%)를 고정 씨앗 파스텔 색으로 채운 것이다. 모양 안을 나누는 선과 자르기 모양은 칠하지 않는다. 그림을 바꾸면 같은 방법으로 다시 만든다: `doodleParade.ts`의 `DOODLE_PARADE` 글에서 `<path d="..."/>`(면 속성이 없는 것)에 `fill`을 넣고, 첫 경로(바탕 언덕)와 액자 안 바탕 사각형에 색을 준다.
