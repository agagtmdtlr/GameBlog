# 플레이어 캐릭터 구조 분석

구체 몸과 키프레임 클립으로 움직이는 두 다리로 된 플레이어 캐릭터의 구조다. 다리는 엉덩이에서 발끝까지 하나로 이어진 스킨 메시다.

- **규칙:** [rules/character.md](../rules/character.md)
- **색인:** [docs/README.md](../README.md)
- **분석 기준:** 커밋 `cc0d160` (2026-11-21, 전체 문서 재검토)
- **최신 여부 확인:** 아래 명령에 결과가 있으면 그 변경분만 확인해 이 문서를 고친다.

```bash
git log --oneline cc0d160..HEAD -- tools/blender src/content/common/character/character.glb src/content/common/character/characterGraphics.ts src/content/common/character/walker.ts src/content/common/character/characterClips.ts src/content/common/character/keyframes.ts src/content/common/character/player.ts src/content/planet/world.ts src/engine/render/renderer.ts src/engine/skinning.ts
```

## 흐름

| 단계 | 파일 | 하는 일 |
|---|---|---|
| 모델링 | `tools/blender/build_character.py` | Blender 스크립트로 다리 스킨 메시 `Leg`와 뼈 `Thigh`, `Shin`, `Foot`을 만들어 `src/content/common/character/character.glb`로 내보낸다 |
| 물리 | `content/common/character/player.ts` | 반지름 0.88 × `CHARACTER_SCALE`(1.32)의 보이지 않는 충돌 구. 중심이 몸의 중심이고, 반지름이 다리가 몸을 받치는 높이다. 굴러가는 회전은 계산하지 않는다. 행성 말고도 `obstacles`로 받은 상자(지금은 텔레비전과 로켓 자리)와 충돌한다 |
| 클립 | `content/common/character/characterClips.ts`, `content/common/character/keyframes.ts` | 서기·걷기·내딛기 키프레임 클립과 트랙 샘플링 |

| 모델 불러오기 | `content/common/character/characterGraphics.ts` | `defineCharacterMeshes`가 glb를 `GLTFLoader`로 불러와 기본 자세 정점과 뼈 번호·가중치를 꺼내 `graphics.defineSkinnedMesh('leg', …)`로 등록한다. NPC의 `pyramid` 메시도 여기서 등록한다 |
| 렌더러 | `engine/render/renderer.ts` | 풀의 메시마다 스킨 메시 지오메트리 복사본을 두고 매 프레임 스키닝 결과를 쓴다. 스킨이 등록되기 전에는 그리지 않으므로 몸만 보인다 |

## Blender 다리 메시 규약

오른쪽 다리가 서 있는 기본 자세 하나로 만들고, 게임은 왼쪽 다리에도 같은 메시를 쓴다. 뼈 행렬이 회전과 이동뿐이라 왼쪽 다리는 메시를 뒤집지 않고 돌려서 놓는다. 좌표는 glTF(+Y 위) 기준이며, 스크립트에서는 glTF (x, y, z)를 Blender (x, -z, y)로 옮겨 모델링한다.

| 항목 | 값 |
|---|---|
| 원점 | 엉덩이 관절. +X가 몸 바깥, +Y가 위이고 다리는 Z = 0 평면에 놓인다 |
| 무릎, 발목 | `(0.749, 0.22)`, `(0.72, -1.09)`. 허벅지 0.781, 정강이 1.31. 엉덩이가 몸 위쪽에 붙어(아래 참고) 무릎은 엉덩이보다 0.22, 몸 중심보다 0.55 높아 몸 꼭대기(0.5)보다 조금 위로 솟는다. 정강이는 거의 수직이다 |
| 발 | 발바닥이 발목에서 0.12 아래, 발끝은 +X |
| 뼈 | `Thigh`(엉덩이→무릎), `Shin`(무릎→발목), `Foot`(발목→발끝) |

- 모델은 배율 1의 설계 치수로 만든다. 게임은 뼈 행렬에 `CHARACTER_SCALE`을 곱해 키운다(아래 크기 배율).
- 기본 자세는 `walker.ts`의 `LEG_REST`, `LEG`와 같아야 한다. `walker.test.ts`가 스크립트의 `REST_KNEE`, `REST_ANKLE`, `ANKLE_HEIGHT`를 읽어 비교한다.
- 기본 자세는 서 있을 때 IK가 푸는 자세와 같게 골랐다 (배율 1 기준 몸 높이 0.88, 엉덩이 옆 0.35·위 0.33, 발 옆 1.07). 자주 쓰는 자세에 가까울수록 스키닝 변형이 작다.
- 메시는 점 7개를 잇는 스킨 모디파이어 관에 서브디비전을 적용해 만든다. 엉덩이에서 몸 중심 쪽(`HIP_INSET`, 안쪽 0.1·아래 0.1)으로 더 뻗어 몸 구 안에서 시작하고, 발은 발바닥 아래 정점을 평평하게 깎는다.
- 가중치는 정점에서 뼈 선분까지 거리의 역수 6제곱을 정규화하고 0.01 미만은 버린다. 무릎과 발목 부근이 두 뼈 사이에서 부드럽게 섞인다.
- 게임은 내보낸 뼈의 변환과 역바인드 행렬을 쓰지 않는다. 뼈 번호는 이름으로 [Thigh, Shin, Foot] 순서에 맞춘다.
- 내보내는 속성은 `POSITION`, `NORMAL`, `JOINTS_0`, `WEIGHTS_0`이다. 색과 거칠기는 `World`의 `PLAYER_COLOR`, `PLAYER_ROUGHNESS`로 준다.

다시 만드는 명령:

```bash
"C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" --background --factory-startup --python tools/blender/build_character.py
```

`-- --save-blend`를 붙이면 `tools/blender/character.blend`도 저장한다. 원본은 스크립트이므로 Blender에서 직접 고친 내용은 스크립트에 옮겨야 남는다.

## 키프레임 클립 (`characterClips.ts`, `keyframes.ts`)

- 트랙은 `[정규화 시간, 값]` 키의 배열이다. 키 사이는 Catmull-Rom 접선의 3차 Hermite로 잇고, 반복 클립은 끝과 처음의 접선을 이어 붙인다. 첫 키는 0, 끝 키는 1에 두고 반복 클립은 두 값이 같다.
- 값은 -1~1 정도로 적고 크기는 `walker.ts`의 `WALK_AMPLITUDE`, `IDLE_AMPLITUDE`, `STEP_HEIGHT`가 정한다.

| 클립 | 재생 기준 | 트랙 |
|---|---|---|
| `IDLE_CLIP` | 시간, 2.8초 반복 | `bob`(숨쉬며 무릎을 굽혀 몸이 0.045 내려감), `sway`(옆 0.025), `roll`(엉덩이 2.5°) |
| `WALK_CLIP` | 걸음 위상, 반복 | `bob`(발이 닿은 직후 가장 낮고 디딘 발 위에서 가장 높음, 0.07), `sway`(디딘 발 쪽으로 0.08), `surge`(닿을 때 뒤처졌다 밀며 나감, 0.035), `roll`(드는 다리 쪽 엉덩이가 올라감, 7°) |
| `STEP_CLIP` | 걸음 하나의 진행도 | `travel`(천천히 떼고 착지점보다 7% 더 내밀었다가 디딤), `lift`(빠르게 들고 끝에서 쿵 디딤) |

## 걸음 (`Walker`)

고정 간격(120Hz)으로 `World.fixedStep`에서 `Player.step` 다음에 호출된다. three.js에 의존하지 않는다.

- **방향:** 수평 속도가 0.4보다 빠르면 진행 방향으로 몸을 돌린다(지수 감쇠, 비율 12). 위쪽은 `normalize(몸 위치 - 행성 중심)`이다.
- **서기와 걷기:** 수평 속도가 0.4보다 빠르면 걷기다. 섞는 비율 `walkWeight`가 비율 7로 따라가며 두 몸 클립을 섞는다. 공중에서는 몸 클립을 쓰지 않는다.
- **걸음 위상:** 한 주기(두 걸음)의 거리 = `0.9 + 0.16 × 속도`(최대 2.6). 위상은 `속도 / 주기 거리`로 진행한다. 위상 0에서 왼발이, 0.5에서 오른발이 닿고, 발마다 주기의 55%는 딛고 45%는 든다.
- **발 고정:** 딛고 있는 발은 월드에 고정되어 몸이 그 위를 지나간다. 발의 위상이 드는 구간에 들어서면 남은 구간 시간 동안(0.08~0.4초) `STEP_CLIP`으로 내딛는다. 착지점은 착지할 때의 몸 위치 기준 쉬는 위치에서 진행 방향으로 `0.55 × 주기 거리 / 2` 앞이다. 목표가 움직이면 착지점도 따라간다.
- **걷기 시작:** 들려 있거나 쉬는 위치에서 더 먼 발이 바로 드는 구간에 오도록 위상을 맞춘다.
- **정리 걸음:** 서 있을 때 발이 쉬는 위치(몸 아래 표면에서 오른쪽 축으로 ±1.07)에서 0.05 넘게 벗어나면 한 발씩 0.22초 동안 낮게(높이 절반) 옮긴다.
- **회복:** 딛고 있는 발이 쉬는 위치에서 1.5 넘게 벗어나면 위상과 상관없이 0.14초 동안 내딛는다.
- **발 방향:** 딛는 동안 고정되고 내딛는 동안 진행 방향으로 돈다.
- **공중:** 0.12초 넘게 땅에서 떨어지면 발을 몸 아래로 매단다. 착지하면 걸음 중간(진행도 0.5)에서 이어받아 땅으로 내린다.
- **보간:** 몸, 방향, 엉덩이 기울기, 발 위치와 방향의 이전 값과 현재 값을 들고 있어 `pose(alpha)`가 보간한다. IK는 그릴 때마다 푼다.
- 위 거리 값(쉬는 위치, 보폭, 발 높이, 진폭, 정리·회복 기준, 공중 매달림)은 배율 1 기준이며 코드에서 `CHARACTER_SCALE`을 곱한다. 시간과 각도는 곱하지 않는다.
- 최고 속도(약 10.6)에서 엉덩이에서 발목까지 최대 2.65로, 다리 길이 3.14(2.09 × 1.5)보다 짧아 다리가 곧게 펴지지 않는다.

## 크기 배율 (`CHARACTER_SCALE`)

- `walker.ts`의 `CHARACTER_SCALE`(1.5, 2026-11-21 사용자 요청)이 캐릭터 전체 크기다. 몸 반지름(`BODY_RADIUS`), 충돌 구(`PLAYER_RADIUS`), 다리 뼈 길이, 엉덩이·발 위치, 걸음의 거리 값이 모두 이 배율을 따른다.
- `LEG`, `LEG_REST`, Blender 모델은 배율 1이다. `world.ts`가 지금 뼈의 축에 배율을 곱한 행렬 × 기본 자세 뼈의 역행렬로 스키닝해 메시가 관절마다 같은 비율로 커진다. 스키닝은 균일 배율이 섞여도 법선을 정규화하므로 맞다.
- 카메라 거리와 이동 속도는 배율을 따르지 않는다. 그래서 화면에서 캐릭터가 커 보이고, 같은 속도에서 걸음 수가 줄어든다.

## 다리 IK (`solveLegs`, `solveTwoBone`)

- 엉덩이 = 몸 중심 + 오른쪽 × ±0.35 + 위 × 0.33 (배율 1 기준, `SPHERE_HIP`). `Walker` 생성자의 `hip`으로 바꿀 수 있고, NPC의 모난 몸이 쓴다([npc.md](npc.md)). 축은 `hipAxes(pose)`가 낸다. 몸 구의 바깥 위쪽 약 43°에 붙는다 (2026-11-21 사용자 요청으로 옆 0.45·위 0.05에서 올림). 오른쪽·위 축은 `roll`만큼 진행 방향 축으로 돌린다. 다리 메시가 몸 구(반지름 0.5) 안에서 시작해 이음매가 보이지 않는다.
- 발목 목표 = 발바닥 + 발 위치의 위쪽 × 0.12.
- 무릎은 `옆 + 위 × 2.0` 방향(pole)으로 굽어 컨셉처럼 바깥 위로 솟는다. 닿지 않는 목표면 다리를 곧게 편다.
- 허벅지와 정강이 뼈는 원점이 관절, +Y가 뻗는 방향, +Z가 pole 쪽이다. 발 뼈는 발 위치의 위쪽을 Y로, 발의 진행 방향에서 바깥으로 75° 돌린 방향을 발끝(Z)으로 놓는다.
- `restBones()`가 같은 규약으로 기본 자세의 뼈를 만든다. 규약이 같아야 스키닝 행렬이 기본 자세에서 단위 행렬이 된다.

## 렌더링에서 바뀐 점

- `Material.receivesOccluder`가 켜진 메시(행성)만 몸이 만드는 앰비언트 오클루전을 받는다. 예전에는 구 줄무늬 무늬(`SphereBands`)로 플레이어를 구분했으나 무늬와 함께 지웠다.
- 몸 구는 회전하지 않는다. 생김새가 대칭이라 방향은 다리로만 보인다. NPC의 정육면체·피라미드 몸은 `hipAxes`로 진행 방향을 보고 기운다.
- 스키닝은 CPU에서 한다. 정점이 674개뿐이고, 셰이더와 그림자 패스(`overrideMaterial`)를 그대로 쓸 수 있다. 스키닝한 정점은 월드 좌표라 다리 항목의 `model`은 단위 행렬이고 화면 밖 제외(`frustumCulled`)를 끈다.
- 개발 서버에서 의존성 최적화 중에 three.js가 두 번 불러와질 수 있어, 불러온 메시는 `instanceof` 대신 `isSkinnedMesh`로 확인한다.

## 테스트

`content/common/character/walker.test.ts`: 키프레임 트랙이 키를 지나고 반복 이음매에서 끊기지 않는지, 서 있으면 숨쉬기로 몸만 움직이고 발은 그대로인지, 걸으면 걷기 클립으로 바뀌고 딛는 발이 미끄러지지 않는지 확인한다. 그리고 IK가 마디 길이를 지키고 pole 쪽으로 굽는지, 서 있을 때 발이 양옆 땅에 있는지, 걸을 때 발을 번갈아 내딛고 발목이 발바닥 위에 붙어 있는지, 진행 방향으로 도는지, 멈추면 발을 모으는지, 공중과 착지를 확인한다. 기본 자세가 Blender 스크립트와 같은지, 숨쉬기 한 바퀴 뒤 서 있는 자세의 무릎 높이가 기본 자세와 같은지, 이웃한 뼈의 스키닝 행렬이 관절을 같은 곳으로 옮기는지, CPU 스키닝이 가중치대로 섞는지도 확인한다.

확인하지 않은 것: 실제 키보드·마우스로 오래 걷기, 최고 속도에서 조작감, 모바일. 서기·걷기 클립은 브라우저 창이 가려진 상태에서 스크린샷으로만 봐서, 실제 프레임 속도로 움직임을 보지는 않았다.

## 남은 일

- 발이 땅에 닿을 때의 기울기(발끝 들기)가 없다. 몸 구는 대칭이라 돌리지 않으며 기울기는 엉덩이 위치로만 보인다.
- 키프레임은 코드(`characterClips.ts`)에 있다. Blender에서 만들려면 glTF 애니메이션을 같은 트랙으로 옮기는 단계가 필요하다.
- 선형 블렌드 스키닝이라 무릎을 기본 자세보다 많이 접으면 안쪽이 조금 눌린다.
- 행성 외의 지형이 없어 발 위치는 행성 표면에 투영만 한다.
